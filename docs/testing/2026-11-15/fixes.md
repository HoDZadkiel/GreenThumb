## 已修正

- F01：新增共用會員 session store，透過分頁通知、視窗焦點、重新顯示頁面、網路恢復及 back-forward 導覽重新驗證會員。通知只帶失效訊號，不儲存身分、草稿或 cookie。
- Session Provider 放在根 layout，讓不同路由與快取頁面共用同一會員狀態。舊的非同步回應會被取消並以版本核對，不可覆蓋更新後的身分。
- F02：離開已登入會員或切換到不同會員時，增加編輯器版本並重新掛載私人操作區，清除討論／專欄草稿、圖片網址、預覽、回覆輸入與暱稱表單。首次從訪客登入不增加版本，保留訪客剛寫下的內容。
- 私人資料回應附 `ownerId`；草稿與收藏讀取會核對回應的擁有者，避免將請求途中切換身分的回應放入另一會員畫面。
- 每筆會員寫入攜帶當下編輯器的 `expectedUserId`。伺服器在任何資料庫操作前與實際 session 比對，缺少或不符時回應 HTTP 409；未登入仍回應 401。
- 上述核對涵蓋討論／專欄發表及編輯、草稿儲存／刪除、收藏、暱稱、三類文章的按讚與回覆。身分與權限仍來自伺服器 session 及既有 RLS，輸入的 ID 不授予任何權限。
- 401／409 會使前端清除舊身分並重新驗證，不會把同一份私人內容自動改用新會員重送。已卸載的登入表單也不能用遲到的回應恢復舊身分。

## API 相容性

更新後的寫入請求必須提供 `expectedUserId`。舊分頁缺少此欄位會得到「登入身分已變更，請重新整理後再試。」及 409，需重新整理載入新版本。這是防止舊分頁誤存內容的預期行為。

沒有資料庫 migration、新增環境變數或權限調整。正式站回歸腳本已加入預期會員與一組舊分頁身分不符的拒絕測試；部署後完整 API 回歸應為 53 組。

## 部署後的 Vercel 驗收

目標維持 <https://greenthumb-eta.vercel.app/>，不以 self-host 代替。

1. 在全新分頁載入更新版本，以會員 01 儲存討論草稿；開另一分頁，登出會員 01 再登入會員 02。第一分頁應同步更新並清除會員 01 的內容，不可將其存入會員 02。
2. 使用暫停／延遲分頁通知的情境，讓舊編輯器帶會員 01 的 `expectedUserId`，但 cookie 已屬會員 02；討論及專欄草稿儲存／刪除與發表均須得到 409，會員 02 原內容不變。
3. 分別在討論、專欄及回覆輸入中填入私人測試內容後登出；內容、圖片輸入與已儲存狀態應立即清除。再次登入其他會員及返回快取頁面，不可重新出現前一會員的輸入。
4. 訪客先撰寫再登入，尚未儲存的訪客內容應保留；同會員重整仍可還原雲端草稿。
5. 執行正式站 API 腳本、保存更新後截圖，清理有 QA 標記的測試內容並核對原會員資料。

原驗收中的失效圖片提示是低優先度體驗觀察，不屬於這次兩項草稿隔離修正；仍保留於原報告。
