# GreenThumb 帳號、註冊與積分制度

版本：MVP 設計提案，2026-11-02。此文件定義規則，尚未實作資料表或會員介面。

## 設計原則

- 使用 Email 與密碼註冊、登入，交由 Supabase Auth 管理密碼及驗證信。
- 訪客可以閱讀；驗證 Email 後即可參與，不需要先賺積分。
- 積分稱為「綠芽積分」，用於顯示貢獻與成長稱號，不可交易、兌現或購買。
- MVP 不設簽到、連續登入獎勵、排行榜或積分兌換，鼓勵分享而非打卡。

## 帳號與公開資料

| 欄位 | 規則 |
|---|---|
| Email | 登入與收驗證信使用，不放入公開 profiles |
| 密碼 | 至少 12 字元，允許貼上與密碼管理器；由 Auth 驗證及儲存 |
| 暱稱 | 必填 1–40 字元，可重複，沿用 display_name |
| 使用者名稱 | 系統自動產生；可於設定修改，沿用小寫英文、數字、底線 3–20 字元的唯一 username |
| 頭像、簡介 | 選填；頭像沿用站內圖片處理規則，簡介最多 500 字元 |
| 種植環境 | 選填，沿用既有 region 選項，不收精確地址 |

公開頁顯示暱稱、@username、頭像、簡介、地區、加入日期、稱號與積分總數。
Email、登入資料、完整積分明細及管理備註不公開。

沿用 member、moderator、admin 角色，角色只由管理員任命，與積分完全分開。

| 身分／狀態 | 能做的事 |
|---|---|
| 訪客／未驗證帳號 | 閱讀公開文章、搜尋與瀏覽植物分類 |
| 已驗證會員 | 發文、回覆、按讚、收藏、檢舉、管理自己的資料與內容 |
| 版主 | 會員功能，加上既有內容管理權限；不能改角色或自行調整積分 |
| 管理員 | 管理角色、停權及更正有問題的積分紀錄 |
| 停權帳號 | 保留公開閱讀能力，禁止會員寫入操作及新積分入帳 |

停權是帳號狀態，不是第四種角色；停權不自動清空既有積分。

## 註冊與登入流程

1. 註冊表單只收「暱稱、Email、密碼」，並要求同意社群規範與隱私說明。
2. 送出後提示前往信箱驗證；重寄按鈕倒數 60 秒，寄信限制仍由伺服器執行。
3. 驗證連結成功後建立登入狀態；只有 Auth 確認 Email 已驗證，才能啟用會員寫入與一次性的註冊積分。
4. 頭像、地區、簡介可稍後設定，不阻擋開始使用。
5. 登入僅使用 Email、密碼；提供登出、忘記密碼、重設密碼。

- 沿用註冊即建立 profile 的 trigger；profile 存在不代表已驗證，權限必須檢查 Auth 的驗證狀態。
- 若 profile 建立失敗，顯示可重試的錯誤，不以瀏覽器假資料代替。
- 重寄驗證與忘記密碼一律使用中性訊息，例如「若此信箱符合條件，我們會寄送信件」，避免揭露帳號是否存在。
- 驗證信過期提供重寄；轉址只允許站內目的地。
- 表單進行中防止重複送出，錯誤保留已填 Email 與暱稱，不保留密碼。
- 註冊與寄信使用 Supabase 的伺服器端限制；上線前配置自訂 SMTP、正式網址與允許的回呼網址。
- Google 登入、手機驗證與雙重驗證不納入第一版。

## 綠芽積分

| 事件 | 積分 | 條件與上限 |
|---|---:|---|
| 首次完成 Email 驗證 | +5 | 每帳號一次 |
| 當日第一篇發文 | +3 | 成功發布且未刪除；每日只獎勵第一篇 |
| 當日第一次回覆別人的文章 | +2 | 成功發布且未刪除；每日只獎勵第一次 |
| 回覆被選為最佳解答 | +10 | 由發問者選取；自己問題下的回覆不加分；每題同時最多一份獎勵 |

- 每日以 Asia/Taipei 的 00:00–23:59:59 為界，使用資料庫時間。
- 一般參與每日最多 +5，最佳解答另計；同時請求也不能突破每日上限。
- 單純登入、發出或收到讚、編輯、收藏、檢舉都不加分。
- 超出當日獎勵次數仍可正常發文與回覆，不因積分限制互動。
- 例如：驗證 +5、首篇發文 +3、首次回覆別人 +2、被選為最佳解答 +10，合計 20 分。

## 撤銷、刪除與防止重複領取

- 被獎勵的文章或回覆刪除、軟刪除時，撤銷該內容的獎勵；刪除問題也撤銷其最佳解答獎勵。
- 取消最佳解答扣回該筆 +10；改選其他回覆，在同一交易內先撤銷舊獎勵，再給符合條件的新作者。
- 同一回覆反覆選取、取消、再選取，只改變目前有效的 +10，不能累加。
- 刪除後不補發當日獎勵名額；在同日再發文或回覆不能重新領取。
- 內容還原時只恢復原獎勵及原日期名額，不算還原當日的新獎勵；最佳解答仍須是目前有效的選取。
- 編輯內容不會新增獎勵；預設不額外扣除懲罰分，違規內容以撤銷對應獎勵與停權處理。
- 管理員更正必須附理由並留下紀錄；不能直接覆寫總分。任何扣回不得超過原事件尚未撤銷的額度。
- MVP 不保證阻止多帳號互刷；先用驗證信、每日參與上限及檢舉管理降低誘因，觀察後再決定額外措施。

## 成長稱號

| 目前有效積分 | 稱號 |
|---|---|
| 0–19 | 小小種子 |
| 20–59 | 萌芽新手 |
| 60–149 | 綠葉夥伴 |
| 150 以上 | 綠手指 |

- 稱號依目前有效積分即時計算；撤銷積分後可能降級，不另存一份等級。
- 稱號是參與紀錄，不代表植物專業認證，也不解鎖版主權限。
- 新會員從 0 分即可使用完整會員功能。

## 頁面與互動

- 頂部：未登入顯示「登入／加入社群」；登入後顯示頭像與選單。
- 註冊：配合既有森林綠視覺，標題「一起，把綠日常種起來」；欄位保持單頁。
- 未登入點發起討論：先登入，成功後返回原入口；既有本機草稿保留。
- 個人選單：我的頁面、帳號設定、綠芽積分、登出。
- 積分頁：顯示目前總分、稱號、距下一級差額、當日發文與回覆獎勵狀態、個人明細；最高級顯示「持續分享，讓綠意生長」。
- 每筆明細顯示時間、原因、加減分及關聯內容；已刪內容僅顯示「內容已移除」，不洩漏被隱藏文字。
- 個人公開頁只顯示總分與稱號；獎勵入帳後用小提示通知，不打斷閱讀。

## 最小實作方式

- 沿用 auth.users、profiles；不建立第二套密碼或登入帳號資料表。
- profiles 增加受保護的 is_suspended，與 role 一樣禁止會員自行修改。
- 新增 points_ledger：id、user_id、event_key、event_type、source_type、source_id、delta、reverses_entry_id、business_date、created_at；管理更正另附操作者及理由。
- 明細只允許本人與管理員讀取；客戶端不得新增、修改或刪除。需要公開的總分以只回傳總額的受控查詢提供，不公開原始明細。
- MVP 從明細加總總分，不在 profiles 維護第二份可修改的 points 欄位；稱號由總分推導。
- 加分、扣回均新增明細，不刪除原紀錄；以伺服器產生的唯一 event_key 防止重試重複入帳。
- 使用資料庫 trigger／受控函式，將內容異動與獎勵寫入同一交易；每日獎勵須鎖定會員後判斷，最佳解答異動須鎖定問題後計算。
- 所有會員寫入 policy 都需檢查已驗證且未停權，不能只在頁面隱藏按鈕，也不能依賴舊登入憑證中的停權狀態。
- security definer 函式使用空 search_path、完整 schema 名稱及最小執行權限；金鑰與管理權限不進瀏覽器。
- 上述規則由程式與資料庫判斷，不使用 AI 決定積分。
- 實作時新增 migration，保留既有版本；先確認實際 migration 可重播，再接會員與積分功能。

## 驗收案例

- 重送註冊、重複驗證連結或重新登入，不會重複得到註冊獎勵。
- 訪客、未驗證與已停權會員，即使直接呼叫 API 也不能新增內容或操作積分。
- 會員無法修改自己的角色、停權狀態或任何人的積分；也無法讀取他人明細。
- 同日同時發出兩篇文章最多 +3；首次回覆自己文章不占名額也不加分。
- 台北時間 23:59 與隔日 00:00 分屬不同獎勵日期。
- 刪除當日得分文章後再發一篇，不重新得分；還原原文只恢復原分數。
- 最佳解答由 A 改為 B、取消、再選 B，任一時刻全題有效獎勵最多 +10。
- 被採納的回覆或問題軟刪除後撤銷獎勵；重試同一操作不重複扣分。
- 積分降過門檻時，稱號與下一級差額同步正確更新。
- 驗證、重設密碼連結過期有明確提示；登入後能返回原發文入口與本機草稿。
