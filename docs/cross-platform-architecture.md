# GreenThumb 跨平台論壇設計評估

評估日期為 2026-11-04。此提案以台灣植物論壇、公開文章搜尋、單人維護成本，以及最終推出商店版 App 為假設。

## 架構選擇

第一階段用現有 Next.js 做一套響應式網站，涵蓋電腦與手機，接著提供可安裝到主畫面的 PWA。正式商店版 App 建議用 Expo／React Native，與網站共用 Supabase 的文章、附件、會員及權限。等到網站與跨裝置發文流程穩定，再開發商店版。[Next.js PWA 指南](https://nextjs.org/docs/app/guides/progressive-web-apps) · [Expo Router](https://docs.expo.dev/router/introduction/)

| 做法 | 介面共用程度 | 適合 GreenThumb 的情境 |
|---|---|---|
| Next.js 響應式網站與 PWA | 同一套頁面、編輯器與樣式，依畫面寬度排版 | 最快驗證產品，可從主畫面開啟 |
| Next.js 網站＋Expo App | 共用資料、規則與設計變數，App 有自己的原生畫面與發布流程 | 確定要上架，並提供推播、系統分享或離線草稿等手機體驗 |
| Next.js 網站＋Capacitor App | 可共用 Web 元件，App 需可打包的前端與資料 API | 商店版仍希望大量共用 Web 編輯器，願意處理原生整合 |

Capacitor 的遠端 server.url 用於開發時即時重載。正式 App 應規劃打包的網頁前端。Next.js 靜態匯出對 Cookies、Server Actions、動態路由和 ISR 有限制，因此公開 SEO 網站與 App 前端仍需要各自的建置策略。Apple 也要求 App 具備足夠的功能與操作體驗。[Capacitor 設定](https://capacitorjs.com/docs/config) · [Next.js 靜態匯出](https://nextjs.org/docs/app/guides/static-exports) · [Apple 審查指南 §4.2](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality)

## 「一處編輯」如何成立

| 修改什麼 | 儲存位置 | 各端何時看到 |
|---|---|---|
| 文章、回覆、照片 | 同一套正式 Supabase 資料 | 重新讀取後看到最新內容。發布、編輯和刪除都須更新快取 |
| 私人草稿 | 以會員為擁有者的伺服器草稿 | 登入同一帳號後可續編。目前原型的瀏覽器草稿須升級成跨裝置儲存 |
| 網頁介面 | 同一套 Next.js 元件與樣式 | 網站部署後，電腦、手機和 PWA 取得更新 |
| 商店版 App 介面 | Expo 元件與共用設計變數 | 經 App 發布流程更新。相容的 JavaScript 變更可用 Expo Update，原生程式碼變更需新建置 |

商店版 App 的 UI 更新受執行環境相容性及發版節奏影響。[Expo Update 相容性](https://docs.expo.dev/eas-update/runtime-versions/)

## 同一篇文章的呈現方式

- **內容**。第一版沿用標題、內文文字與有順序的附件清單。圖片保存 ImgBB 直連及替代文字，各端讀取同一份資料。需要在段落中插入圖片或植物照護卡時，再統一升級成有版本的內容區塊。
- **版面**。共用標題、段落、附件順序、連結與最佳解答的呈現規則。圖片保持比例，長標籤和網址可換行。不同螢幕保留自己的閱讀寬度和導覽。
- **編輯器**。各端都能建立、移除、排序圖片並預覽。桌機可並排編輯與預覽。App 用全螢幕編輯，支援貼回 ImgBB 直連，並在返回畫面後載入草稿。第一階段沿用目前的 ImgBB 上傳引導。
- **規則**。會員身分、停權、發文權限、最佳解答與積分由同一個服務端規則處理。Web 與 App 讀取同一份授權結果。維持同一文章 ID 與公開網址，讓 Google、分享連結與 App 都能指向同一篇文章。
- **同步**。登入草稿採自動儲存與可見的儲存狀態。編輯已有內容時帶原版本，兩裝置同時修改便提示載入新版本，保留尚未送出的文字。

## 各端畫面

| 介面 | 主要設計 |
|---|---|
| 電腦版 | 討論列表搭配物種、地區側欄。文章正文保持適合長文的欄寬。發文區左編輯、右預覽，方便寫教學與整理照片 |
| 手機網頁 | 單欄閱讀，分類及地區收在篩選區。提供搜尋、公開文章和完整發文功能，使用同一公開網址 |
| App | 全螢幕閱讀與編輯，底部提供探索、收藏、我的。發文入口可從主畫面及草稿清單進入，照片可點開檢視 |

顏色、字級層次、間距與狀態用詞以同一份設計變數維護。Web 的 CSS 與 App 的原生元件各自消費這些變數，並使用同一份示範文章檢查內容呈現。

## 導入與驗收

1. **完成響應式論壇**。先接上公開文章、會員、發文和附件資料。驗收桌機與手機能依同一網址讀取相同標題、內文、圖序與回覆。
2. **加入跨裝置草稿與 PWA**。驗收在桌機寫到一半，手機登入後能續編，發布後所有裝置讀取同一版本。另測同時編輯、斷圖、刪文與快取更新。
3. **推出商店版 App**。先以探索、閱讀、發文、收藏及會員流程為範圍。用同一篇含長標題、多圖、地區標籤及最佳解答的測試文章，在桌機、手機網頁及 App 驗收內容完整性。網站與 App 分別驗證並發布，服務端變更保留對已安裝舊版 App 的相容性。

此評估依現有論壇設計和官方框架文件提出，跨裝置草稿、原生 App 與商店送審仍待實作和實機驗證。
