# GreenThumb 圖片外連與成本轉移研究

- 研究日期：2026-11-03（Asia/Taipei）。
- 範圍：PTT 式貼圖、第三方圖床、成本歸屬及 Next.js／Vercel 導入方式。
- 狀態：研究與設計建議；未變更網站功能、資料庫或外部帳戶。
- 方法：查閱 PTT 原站討論及供應商官方文件；下列建議是依 GreenThumb 需求所作的工程判斷。

## 1. 結論

建議 MVP 採「使用者自行上傳外部圖床、貼入連結，瀏覽器直接載入」；精華教學與照護卡日後再經作者授權保存於 R2。這能降低站方圖片儲存與傳輸用量，但會增加使用者操作，並將保存可靠度交給外部服務。

尚不建議整合全站共用圖床 API 帳號，也不要求會員交出 API Key。前者仍集中消耗站方帳戶額度，後者增加註冊與憑證管理負擔。

## 2. PTT 模式是否可行？

PTT 新手板教學明確描述：先把圖片上傳圖床，再貼圖片網址；PTT 本身不提供檔案上傳空間。這支持外連模式的可行性，但該教學是歷史操作資料，不代表目前所有 App 都支援相同圖床或自動開圖方式。[PTT 原站教學](https://www.ptt.cc/bbs/PttNewhand/M.1627311661.A.A1F.html)

「使用者自己上傳」與「必須自己註冊」是兩回事，是否需要帳號由圖床決定。例如 Postimages 提供匿名上傳，但刪除管理與隱私設定有差異。[Postimages FAQ](https://postimages.org/faq)

GreenThumb 可以實作相同概念；自動預覽是本網站自己的功能，不能直接假設 PTT 或其他閱讀器的開圖規則可沿用。

## 3. 成本實際由誰承擔？

| 模式 | 儲存與圖片傳輸 | 站方仍需承擔 | 判斷 |
|---|---|---|---|
| 只貼來源頁連結，點擊開啟 | 外部圖床 | 網頁、文字資料與連結管理 | 最省，但閱讀會離站 |
| 外連圖片，瀏覽器直接載入 | 外部圖床 | 網頁、網址紀錄、內容管理 | MVP 首選，前提是服務允許嵌入 |
| 站內串第三方上傳 API | 第三方服務及所用帳戶 | 整合、額度管理；經伺服器轉傳另有運算／流量 | 不等於把成本交給會員 |
| 每位會員連接自己的儲存帳戶 | 各會員帳戶 | 授權與客服支援 | 第一版過於繁瑣 |
| 站方 R2 | 站方帳戶 | 儲存、請求、圖片處理及備份 | 保存重要內容時採用 |

純外連不會自動產生 Supabase Storage 檔案用量；網站頁面與網址資料仍有正常成本。若站方代抓、轉圖、建立縮圖或備份，就會重新產生對應成本。

## 4. 候選圖床查核

| 服務 | 官方文件可確認的事項 | GreenThumb 建議 |
|---|---|---|
| Postimages | 提供論壇分享；條款禁止自動／程式化上傳，要求盡可能讓嵌入圖片回連來源頁；大量使用可能被要求調整方式 | 優先做人工上傳與回連預覽測試；不可當作已核准的站內上傳 API |
| ImgBB | API 提供圖片直連與來源頁，並可設定自動刪除期限 | 列為候選；API 存在不代表無限額度或永久保存，先確認實際用途及服務條款 |
| Imgur | 論壇使用須符合規則；禁止商業圖片託管及把 Logo、頭像等當作 CDN 素材 | 不綁定為唯一預設；網站加入廣告或其他營利方式前須重新評估 |
| Catbox | 商業外連需事前同意；匿名檔案兩年無存取會移除，帳戶檔案的保存政策不同 | 不作精華內容的唯一存放地，也不使用臨時 Litterbox 連結 |

依據：[Postimages 條款](https://postimages.org/terms)、[ImgBB API](https://api.imgbb.com/)、[ImgBB 條款](https://imgbb.com/tos)、[Imgur 論壇 FAQ](https://help.imgur.com/hc/en-us/articles/26509006740891-FAQ-for-Forum-Users)、[Catbox FAQ](https://catbox.moe/faq.php)。

補充：Postimages 表示不因閒置刪圖，但這不等於保證永久可用；其匿名上傳保留 EXIF，登入者可透過設定移除。發文教學應提醒使用者先移除照片定位等資訊。[Postimages FAQ](https://postimages.org/faq)

上述資料不構成特定用途已獲供應商同意的證明。尚未取得帳戶實際額度、進行上傳或台灣不同網路的可用性測試，因此目前沒有正式啟用的圖床白名單。

### 2026-11-04 補充：Imgur 與 ImgBB 的持久性比較

兩家之中，建議先測試 **ImgBB**。它提供圖片直連與來源頁，上傳可選擇是否設定自動刪除期限。建議會員登入後上傳並關閉自動刪除，方便日後管理。ImgBB 條款保留刪除內容、停用帳號及限制商業用途的權利。免費帳號的實際外連行為仍需在 GreenThumb 網域測試。[ImgBB 上傳頁](https://imgbb.com/)、[API 文件](https://api.imgbb.com/)、[使用條款](https://imgbb.com/tos)

Imgur 明確允許符合條款的論壇圖片外連。官方也公布針對未綁定帳號的舊有、未使用且不活躍內容的清理政策，長期不活躍的帳號亦可能移除。若使用 Imgur，建議登入上傳並維持帳號活動。[論壇外連說明](https://help.imgur.com/hc/en-us/articles/26516761846171-I-can-t-see-the-images)、[匿名舊圖政策](https://help.imgur.com/hc/en-us/articles/26479362527771-Imgur-Terms-of-Service-Update)、[帳號不活躍政策](https://help.imgur.com/hc/en-us/articles/26479520847643-Inactive-Account-Policy)

這項排序依據是貼圖流程及保存設定。兩家缺乏可比較的長期連結存活資料。伺服器保存可替換的圖片直連、來源頁與說明，瀏覽器直接開圖。斷圖時保留說明與來源，讓作者在原文補上新網址。對於缺圖就難以理解的精華內容，優先取得作者授權並保存檔案副本。

## 5. Next.js／Vercel 的費用陷阱

圖片網址存在外部，不代表圖片傳輸一定避開 Vercel。若使用預設圖片最佳化，來源圖片仍可能由 Vercel 取得、轉換與傳送，計入相關用量。[Vercel 圖片計價](https://vercel.com/docs/image-optimization/limits-and-pricing)

建議外連圖統一使用 next/image 的 unoptimized 模式，確保 src 是供應商直連網址，不經站方代理。此模式不改變尺寸、畫質或格式；不能據此宣稱外部原圖已壓縮。站方自有主視覺不必跟著停用最佳化。[Next.js Image](https://nextjs.org/docs/app/api-reference/components/image)、[Vercel 用量管理](https://vercel.com/docs/image-optimization/managing-image-optimization-costs)

驗收以瀏覽器 Network 為準：會員外連圖應直接請求核准圖床，不能出現對應的 /_next/image 轉圖或自建代理請求。不要只看畫面有成功顯示。

## 6. GreenThumb MVP 設計

### 發文與閱讀

1. 提供「加入圖片連結」，每篇最多 5 張，回覆最多 3 張；此為產品建議上限。
2. 分別保存來源頁網址、圖片直連網址與說明文字。來源頁不是圖片本身，不能直接當 img 的 src。
3. 只接受審核過的 HTTPS 圖片主機；未知來源保留一般外部連結，不自動抓網頁解析圖片。
4. 可預覽的圖片依供應商要求回連來源頁，使用延遲載入與預留版面空間。
5. 不接受使用者提交任意 HTML、script 或 iframe；需要官方嵌入時另作專用支援。
6. 失效圖片顯示說明與來源連結，作者可編輯補圖；不自動刪除文章或宣告原圖永久遺失。
7. 頭像先使用字首／內建選項，Logo 與品牌素材留在專案。

### 需要明確接受的取捨

- 外部主機可接收到讀者的圖片請求資訊；貼圖介面應告知外部載入，並評估 Referrer-Policy 與按需載入。
- 外圖尺寸及內容可在貼出後改變；縮小 CSS 顯示尺寸不會減少原圖下載量。
- 外部圖床可刪除或封鎖圖片；站內刪文也不會同步刪除會員在圖床的原檔。
- 不以伺服器對任意網址作 HEAD／GET 驗證。未來若加入備份，須驗證目的主機、重新導向、檔案大小與類型，避免變成任意網址抓取服務。

### 與現有規格的衝突

目前 CLAUDE.md 要求上傳圖片先壓縮為 WebP；純外連無法強制處理使用者已上傳的原圖。若採本提案，應明訂此規則適用於「由站方接收或保存的檔案」，外連則提供壓縮建議。本次沒有修改該約定。

目前 images.storage_path 為非空且代表站內儲存路徑，不應直接塞入外部 URL。MVP 建議以獨立的外連圖片紀錄承載網址與作者／文章關聯；正式實作時另作 migration，明確限制編輯權限與文章／回覆歸屬。本次不建立資料表。

## 7. 重要內容保存與預算

外連適合降低起步成本，但精華教學、植物辨識比較照與照護卡應有保存策略。建議由作者提供原檔並明確授權後，再轉為站方管理的 WebP 與縮圖；不自動搬運所有外連圖。

R2 Standard 現行每月免費額度為 10 GB-month 儲存、100 萬次 A 類操作、1,000 萬次 B 類操作；超額儲存 US$0.015／GB-month，不收傳出流量費，請求另計。[R2 官方計價](https://developers.cloudflare.com/r2/pricing/)

估算例：若只保存 1,000 張精選圖，每張成品 250 KB，加一張 50 KB 縮圖，約占 0.30 GB。這是十進位容量估算，不含原檔、版本與備份，也不是可用性或永遠免費的保證。

開始保存後，需另行安排備份、刪除與快取失效；免傳出流量費不能取代資料保存工作。

## 8. 導入順序與驗收

| 階段 | 工作 | 完成標準 |
|---|---|---|
| A：供應商確認 | 選 1–2 家候選，核對條款、回連與未來營利用途 | 每家有明確支援範圍；不清楚的先只提供外部連結 |
| B：實際貼圖測試 | 作者自行上傳，手機／桌機閱讀，檢查匿名與登入管理方式 | 台灣實際網路可用，來源頁與直連辨識正確 |
| C：MVP 功能 | 加入連結、預覽、圖片說明、失效提示、權限檢查 | 無站方圖片代理、未授權編輯及任意 HTML 注入 |
| D：觀察 | 記錄貼圖完成率、載入失敗回報、供應商問題及客服負擔 | 根據真實問題決定更換圖床或增加站方上傳 |
| E：精華保存 | 經作者授權保存至 R2 | 圖片可回復、可刪除，有可追溯的來源與授權紀錄 |

不以所有讀者都看不到圖片作為單一瀏覽器載入失敗的結論，也不以成功開啟圖床首頁作為外連穩定性的證明。

## 9. 建議決策

先採 PTT 式人工上傳與外連，優先驗證 Postimages 的回連流程，ImgBB 作第二候選；在完成實測前不承諾任何一家永久可用。精華內容保存列為獨立的後續功能，保留原先 Supabase 會員與文章架構。

本報告只處理圖片成本與保存策略；Mailgun 額度與會員積分制度不在本次範圍。所有外部限制與價格均需在正式啟用時再次核對。
